1a · Layout notes
lupin
Wordmark: lowercase lupin in Nunito.
Messages

Empty states and warnings use text in a notched bubble. No sprite images.

What I'd change across the app
  1. Persistent sidebar replaces the header link row (all work / usage / reload). Pages are Overview, Machines, Loops, Schedule, Repos, Roadmap, Usage, Models, with live counts as badges.
  2. One status bar on every page: timer state, next run countdown, auto-refresh. Today this exists only on the dashboard.
  3. Overview answers three questions in a top row: what is running, when is the next run, does any quota need attention.
  4. Live loops become compact rows with a status dot and a two-line tail. The full pane opens on click, so five loops no longer push everything else off screen.
  5. Schedule and quota sit beside the loops, so you see them without scrolling. Quota gets a compact form with a link to the full page.
  6. Repos is its own page. The table gains Schedule… (one-off run) as a row action rather than an inline text field.
  7. Usage: lead with projected run-out, put providers in one comparison grid so windows line up, and demote token totals to a table below.
  8. Dark mode: toggle at the bottom of the sidebar, or the Theme tweak.
  9. Color: green means healthy. Orange is only for things that need you: quota ahead of pace, blocked issues, stale or failed data, destructive actions.
  10. States: the Scenario tweak shows empty (no loops, no repos, no issues) and a provider failing. Close gracefully on Loops ends in a stopped state.
  11. Messages: empty states, confirmations, warnings and failures are spoken in a notched bubble.
  12. Machines: a loop is repo + number + machine (api-gateway #3 on mini-2). The fleet shares one capacity, so the page shows each slot's limit once, at fleet level, and never as a per-machine limit. A machine card shows the machine's state (online, draining, offline), its version, its heartbeat and its loops. A machine can be drained, lose heartbeat, or fall behind on version; each state has its own message.
  13. Roadmap: a board for a few dozen issues, a paged list with epic grouping at scale. Select issues to start a quest. Blocked issues that need a person are called out at the top. Issues that need a specialist carry a capability tag (frontend-ui, translation, prose, cad-spatial, general) that matches the categories on Models. Coding is the default and is not shown, but it can still be filtered. Work goes to the model that is strongest in that category.
Mockups: 1b Overview, 1c Usage, 1d Loops, 1e Schedule, 1f Repos, 1g Roadmap, 1h Models, 1i Mobile overview, 1j Roadmap at scale, 1k Machines. All colors are driven by Tweaks. Data is sample.
